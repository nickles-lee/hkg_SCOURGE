## Review follow-up (latest-main integration)

The first independent review of this latest-main merge blocked the new
`UPDATE-OVER-SSH` hot-swap path. The fixes are included here: the live binary
is backed up and read back **before** the unit is stopped; the replacement is
written to a same-directory temporary, label-fixed and renamed atomically; an
EXIT/signal recovery restarts the unchanged daemon if a pre-install step fails
and restores the backup (including recorded `SMACK64`/`SMACK64EXEC` labels) on
a post-install failure; success requires a verified API response and, when
`ssh=1`, the listener; a missing probe tool fails closed before the stop. The
procedure document no longer disables host-key verification and its ELF,
`ssh=0` and listener claims match the script. `test_hotswap.sh` exercises the
success, already-current, backup/install failure, no-API rollback, `ssh=0` and
missing-probe cases.

The Wifi1b, Tweaks and WiFi payload builders now `make clean` before rebuilding the daemon because the
embedded build identity hashes `scripts/` as well as `src/`; an incremental
make after a script-only change could otherwise stamp a new identity onto an
old binary. The current Wifi1b release identity is `be16fbc615a4`.
